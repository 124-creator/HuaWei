## 2. 资源与问题规模（配【图F01】【图F03】）

- **资源（图F01）**：计算单元与L1/UB按核心独立；DDR带宽60 bytes/cycle由全部核心共同竞争——核心数增加不会等比例增加带宽。三场景共用这套硬件；只有问题三增加一块1 MiB、250 bytes/cycle的共享只读L2，独立于DDR。图中画出的核心仅为代表，不表示固定只有三个核心。
- **规模（图F03）**：100张官方计算图；非COPY操作数范围为552至35705，M/V计算组成差异明显——固定切分尺度不可能对所有图都合理，这是后文"按图结构自适应切分"的动因。
- 全文共1400个最终配置（A 400＋B 500＋L2 500）；这不是1400个独立样本（口径提醒，若引用需保留原意）。

## 3. 决策结构与可行性（配【图F02】）

- **决策三元组（式(1-1)）**：P=(g,a,π)——操作划分g、核心归属a、核上顺序π。输出只含两个字段；操作的开始时刻由官方Step1/2/3确定，算法不能自由指定。
- **可行性（式(1-2)）**：①覆盖性——每个非COPY操作恰好分到一个子图；②唯一排布——每个子图只出现在一条核心队列中一次；③**联合无环**——数据依赖边与核心队列顺序边的并图必须无环（原始DAG无环不足以保证这一点：核序引入的顺序边会与数据依赖边构成新的有向图，可能形成等待环）。联合无环不代替容量与带宽检查。
- **三个场景共用同一决策结构**，差别只在"Task如何组织"与"评价算子"（见§6）。

## 4. 目标函数与评价口径

- **黑箱目标（式(1-3)）**：T(P)=Makespan(Eval(G,P;θ))，单位cycles；场景B为同形式（式(2-1)）；问题三使用加了L2配置的同一套评价（记T_L，见第7章）。把官方评价器当作确定性黑箱目标是刻意的建模选择：收益是与官方口径零偏差，代价是无法对最优性给出解析保证——本文并不宣称求解"可自由选择每个操作开始时刻"的精确混合整数规划。
- **择优方式（式(1-4)）**：字典序——先比较Makespan，相同时再比较新增COPY字节数。
- **基准REF**：原版核内调度算法在整图单核上的结果；不使用各方法自行优化后的单核结果作分母；单核加速比按定义为1。
- **加速比口径（式(1-13)）**：先逐图求比值、再取算术平均；不用"平均耗时之比"替代。
- **对照基线C3**：可复现的固定构造基线——合并安全链、按就绪层平衡计算负载、用等待与边界代理分核、一次成型后不再迭代。它与R12使用相同输入、相同官方评分口径；C3是**事后同口径对照，不是等搜索预算的消融实验**，两者的终点性能差不能解释为等成本下的算法效率差。
- **与C3的逐例对比口径（式(1-14)）**：逐图耗时降幅先逐图计算再取平均；不是求解程序的墙钟降幅。

## 5. 时序与容量约束（配【图F04】）

- **时序（式(1-5)～(1-7)）**：同核前一Task有100 cycles切换等待（只对同核前一Task计一次，不在每条数据边重复）；跨核数据前驱额外1000 cycles（只在前驱与后继分属不同核心时计入）；两者取大得到必要释放时刻r_s。r_s只是必要条件——Task内部操作还须满足Pipe串行、依赖就绪与内存申请次序。
- **场景B/L2的跨核同步（式(2-4)）**：目标核读入须等源核写出完成并加500 cycles；同样是必要释放条件，不等于"立即发射"。
- **容量（式(1-8)）**：L1=524288 bytes、UB=131072 bytes；约束对象是"时刻τ核心c上容器m的实际活跃驻留集合"，不是该子图的全部张量集合——这一区分直接影响对切图粒度上限的判断（配图F04：单张量尺寸只描述输入尺度，多张量活期重叠仍可能溢出，不能由单张量大小推断运行时峰值）。
- 零周期计算按现行实现的max(1,cycles)处理；保留原始输入，区分文义与实现细节。

## 6. 三个场景的关系（可整理为对照表，用【表4-1】占位）

| 维度 | 场景A（问题一） | 场景B（问题二） | L2（问题三） |
|---|---|---|---|
| Task组织 | 每个子图独立成Task | 每核全部子图合并为一个Task | 同场景B |
| 同核跨Task数据 | 必须经DDR中转 | 不适用（无跨Task边界） | 同场景B |
| 跨核同步 | 前驱完成后+1000 cycles | OUT完成后+500 cycles | 同场景B |
| 主要代价 | Task边界搬运 | 核内驻留/Spill | 缓存交互（命中/逐出） |
| 评价配置 | Eval_A | Eval_B | Eval_L（B配置＋1 MiB只读L2、250 bytes/cycle） |
| 求解策略差异 | 不使用局部微批 | 可用Spill触发微批 | 同B，另做"配置/选解"分离分析 |

- 本章一句话点到即可的两条边界（细节分别在第6、7章）：①场景B不能由场景A替换同步常数平移得到；②L2的收益必须把"硬件配置效应"与"求解器选解效应"分开报告。

## 7. 求解框架总览（细节留第5-7章）

- **框架（R12）**：结构化候选生成 → 官方整机评价 → 字典序择优；每次请求都从原图开始，不读取历史结果表中的优胜方案；全程受600秒软预算约束。
- **组件清单（各一句话，细节在5.2/6.2/7.2节）**：
  1) 控制链：安全链收缩＋依赖带分带＋追加式分核（追加式分核不会由自身引入等待环）；
  2) 反馈重排：利用官方返回的时间段反馈，在划分g不变的前提下重新分核与排序（收益与搬运量解耦）；
  3) 分量家族：活动核数与驻留组织候选的枚举（B/L2）；
  4) 插入式候选：用确定性Treap区间索引加速"最早可行位置"插入（只加快同一插入规则，不改变判定）；
  5) Spill触发局部微批：仅当确有Spill时诊断并重排（B/L2；场景A不适用）。
- **两条性质（各一句话）**：同次请求内不变差（候选必须严格更优才替换当前解）；确定性实现（不依赖随机种子，同配置复跑输出方案的plan_sha256可复现）。
