**表格与算法块的排版（本轮一并处理）。**

- 表5-2、表6-1、表7-2三张“核数×指标”的逐核主结果表共9到10列，在小四号字下无论怎样分配都放不进版心。改为转置排版（行为指标，列为核数），单元格原样搬运，不动数字；转置由源稿中的 `<!-- transpose 核 -->` 标记驱动，Markdown与Word两份输出一致。

**例外，请队伍拍板。** 附录A的逐例表每张100行、最多8列，改用小四号会多出若干页且部分列要折行，仍用五号（10.5 pt）。这属于“其他汉字一律小四”的字面例外；若要严格执行，把 `code/build_docx.py` 中 `three_line(..., small=seen_appendix)` 改为 `small=False` 后重新生成即可。

## 四、任务二、三：按一等奖、特等奖的读法重写

**评委怎么读。** 一篇A题论文，评委先看摘要页，再翻问题分析和各问的结果表、结果图，最后才看模型细节。每一层都要回答同一个问题：这支队伍知不知道自己在解决什么，结果靠不靠得住。本稿的底子是模型与评分口径一致、1400格全量实验、负面结果如实披露，这几项在往届优秀论文里并不多见（见 `01_优秀论文对标分析与第二轮优化.md`）。本轮要做的是让这条主线从第一页起就看得出来。

**一条贯穿全文的逻辑：认代价、造候选、设下界、凭评测。** 以评估程序为目标的调度问题没有闭式目标，我们一贯分四步处理：先查清每个场景的时间花在哪里，再针对主导代价构造结构化候选，然后用与方案无关的下界决定哪些候选不必评价、什么时候可以停手，最后一律用官方评价定案。这四步现在是全文的骨架：

| 位置 | 这条逻辑怎样出现 |
|---|---|
| 摘要首段 | 直接交代四步，三问各段按“代价在哪里—用什么候选—结果多少”展开 |
| 第2章 | 开头点明四步；2.2节从数据普查“认代价”，逐条落到方法选择；2.3至2.5节每问只讲代价结构与对策 |
| 第4章 | 4.7节求解框架按四步组织，门控与下界在一处讲清 |
| 第5至7章 | 每章开头先说该场景的代价重心，流程图（图5-4、图6-4、图7-2）与算法框紧跟其后 |
| 第8章 | 检验按“可不可信、是否偶然、是否稳定、预算是否改变结论”四问组织；新增并行度分析，说明收益由图的结构决定 |
| 第9、10章 | 9.1节四条认识、9.5节推广都回到这四步；结论的四个创新点与摘要一一对应 |

**写法上的几条守则。** 本轮按下面几条逐章改写，也建议队员自己改写时沿用：

1. 每段第一句给结论，后面给证据；数字带口径（“逐例比值的算术平均”“每格100图”）。
2. 不用“显著提升”“至关重要”一类没有数字支撑的形容；“显著”只在统计检验的意义上用。
3. 因果只说到数据支持的程度。数据只显示相关的，写“可能是……的原因之一”。
4. 负面结果主动写：8对L2退化、case_062在低核数的退化、case_087的预算例外都放在正文，不放附录角落。
5. 少用“首先、其次、此外、综上所述”这类套话连接，改用内容本身的承接（“场景B只改了一条规则……”）。
6. 用“我们”陈述自己的选择与理由，用“本文”指代全文结构，不混用。

**题目。** 原题目沿用赛题名“通用神经网络处理器下的多核调度问题”，评委从中看不出做了什么。定稿题目为“基于可证下界与结构化搜索的多核NPU切图调度”：“多核NPU切图调度”交代对象；“结构化搜索”是求解主体，即按代价结构构造候选、以官方评价择优；“可证下界”是全文理论上的保证，负责剪枝与近优认证，也是区别于一般启发式论文的地方。题目为19个汉字加“NPU”，在“题 目：”之后一行排得下。要改，改 `code/build_docx.py` 中的 `TITLE` 一行即可。

**流程图的优化与适配。** 队伍初稿的三问流程图已重绘为图5-4（问题一）、图6-4（问题二）、图7-2（问题三的求解与“方案×配置”受控对照），与算法框对应，红色虚线框标出近优门控的作用范围；图2-3技术路线改为四个阶段。原第二轮的总流程图F37撤下，其内容已分到三张分问题流程图中。第7章原图F23（两种比值的构成示意）由图7-2取代，因为后者已经包含两种比值的构成（队伍已确认）。作图代码在 `code/flowcharts.py`。
